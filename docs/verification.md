## 关闭看画后直接恢复漫游（2026-10-12，本地修改）

- 原因：先前面板关闭只解除场景暂停，未重新请求鼠标锁定，因此总会出现额外的「点击继续漫游」。现在高清关闭按钮、介绍关闭按钮及介绍背景关闭在同一次点击内解除暂停并请求恢复桌面漫游；焦点先归还再锁定，不增加计时器或额外点击。
- Esc 关闭仍保持暂停，保留用户要求的显示箭头/停止随动行为。介绍覆盖高清时，只关闭介绍不会锁定；最后一层关闭返回展厅才恢复。触屏模式不申请鼠标锁定；锁定被浏览器拒绝时沿用可重试入口。
- 参考 [Pointer Lock 2.0 请求规范](https://w3c.github.io/pointerlock/#dom-element-requestpointerlock)：由关闭按钮的用户点击同步触发请求。未改变浏览器权限或绕过原生限制。
- 新增实际 ArtViewer 关闭流程测试，覆盖按钮关闭传递恢复意图、焦点顺序、默认Esc关闭保持暂停及重复关闭；控制器测试覆盖面板仍打开/触屏不锁定、直接恢复及关闭点击不穿透。共25项测试、TypeScript/Vite生产构建及 `git diff --check`通过。
- 浏览器用临时原生锁定适配器运行实际 main/Gallery/ArtViewer：进入、驻足、打开高清、打开/关闭介绍后仍保持高清且锁定请求计数不变；点击高清关闭后立即恢复，未出现继续入口；重开后Esc关闭则保持暂停。浏览器无错误或警告，临时页已删除。适配器验证应用事件链，不代表成功验证原生锁定；原生自动化限制沿用之前记录，未进行真实手机测试，未发布线上站点。
